# 慕容显示增强 v2.9.41

本版修复用户反馈的「刷新率写入失败：ERR request」，并打通 1+15（PLK110）在
ColorOS 17 上的 DRM-KO 注入路径。PLK110 / PLQ110 的档位阶梯统一为
175 / 185 / 195 / 199。

## 修复内容

### 一、Scene / 游戏助手改刷新率报「刷新率写入失败：ERR request」（用户反馈）

刷新率服务的命令表里少收了三条桥接会发的命令：

| 命令 | 谁发 | 语义 |
|---|---|---|
| `SETAPP <pkg> <w> <h> <fps>` | 设置面板、Scene | 按应用设定档位 |
| `SETGLOBALMODE <w> <h> <fps>` | Scene、游戏助手 | 持久化全局模式 |
| `GETALL` | 桥接 | 一次事务读回完整快照 |

这三条在付费守护进程里一直都有实现，免费版却直接落到了命令分派的兜底分支，回一句
「这条命令我不认识」。外部调用方拿到的就是 `ERR request`，最终显示为
「刷新率写入失败：ERR request」。本版把三条补齐，并按各自约定的应答格式返回。

### 二、PLK110 上按几何选档位必然落空

调用方只能描述它在 DisplayManager 里看到的分辨率，而系统会把自己的分辨率偏好
（1440 宽）与实际驱动的 HWC 配置并存。PLK110 的面板模式表里只有 1272x2772 与
1080x2354，于是「宽、高、刷新率」三项精确匹配对**每一个**刚列出来的刷新率都失败。

本版区分两种失败：

- 模式表里**根本不存在**该几何 → 判定为客户端持有过期信息，改用当前实际驱动的几何；
- 模式表里**存在**该几何但不支持所选刷新率 → 仍然如实拒绝，不会把真不支持的档位放过去。

回退时会写明确日志，便于后续排查。

### 三、1+15（PLK110）DRM-KO 注入路径打通

内核模块的设备树预检原先要求树里正好是原厂那六档（含 90Hz 与两个 120Hz）。走 DTBO
后端时档位已经被改过，预检因此必然失败并返回 `-ESTALE`，注入被静默跳过——状态看起来
正常，实际什么都没发生。

本版把预检改成只验证真正被下游依赖的不变量（165Hz 源档位存在且唯一 + 档位数量下限），
未知帧率按「DTBO 已追加的超频档」处理。

**真机实测（PLK110 / ColorOS 17）**：

```
appended 4 mode(s), removed 0 stock low mode(s), count 6 -> 10
applied = Y   cache_applied = Y   failure_code = 0
connector_hotplug_sent = 1   DTBO untouched
```

生效档位 **9 档**：60 / 90 / 120 / 144 / 165 / 175 / 185 / 195 / 199。
DRM-KO 路径**完全不写 DTBO 分区**，比 DTBO 后端少一次分区写入风险，并且保留了
原厂的 90Hz 与 120Hz（DTBO 后端会删掉这两档）。

### 四、注入参数被内核静默忽略

后端脚本原先把 RMX5200 专用的 `drop_stock_fhd` / `phy_profile` 通过一个兜底分支发给了
所有非 PJD110 机型。PLK110 / PLQ110 的内核模块并不声明这两个参数，内核只打一行
`unknown parameter ... ignored` 就继续，意图被静默丢弃且没有任何地方报错。

本版改为按机型分派，每个模块只收到它真正声明的参数。注意没有把 `drop_stock_fhd`
映射成 `drop_stock_low` —— PLK110 的 `OC_DROP_STOCK_LOW_DEFAULT` 是 `false`、
`OC_EXPECT_REMOVED_STOCK_LOW` 是 `0`，它故意保留原厂低刷档，强行传入反而会撞上
移除计数的校验。

### 五、SurfaceFlinger 投票过滤补丁限定为 RMX5200 专有

该补丁修的是 RMX5200 的原厂 LTPS（厂商自己插入的动画投票会被 AP-scale 表解析成错误
档位）。PLK110 / PLQ110 / PJD110 是原厂 LTPO，厂商自己管理刷新率，没有需要过滤的投票。

此前策略文件对所有机型都发 `stock_ltps`，使这个 RMX5200 专用补丁被武装到了未经
验证的机型上；本版按显示 profile 把关，未列入的机型直接跳过。

### 六、档位阶梯

PLK110 / PLQ110 共用同一条设备树生成路径，档位统一为 **175 / 185 / 195 / 199**
（10Hz 等距，末档贴近 200Hz）。按时钟步进算是 +6.1% / +5.7% / +5.4% / +2.1%，
全程无大跳。PLK110 上已实测生效。

## 兼容性

- 支持机型：RMX5200、PLK110、CPH2747、PLQ110、PJD110
- 系统：ColorOS 16 / 17
- 内置内核模块均由固定 commit 的官方源码树重建

## 说明

- **PLQ110 的档位阶梯已按 1+15 对齐，但其「组内 timing 数量上限」是 PLK110 上实测
  出来的经验值，在 PLQ110 上尚未真机验证** —— 首次测试请先确认能开机。
- 若发现开机活跃档位不对，请优先排查生成节点继承的 `qcom,mdss-dsi-timing-default`
  标记。
