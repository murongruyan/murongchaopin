# 慕容显示增强 v2.9.45

本版集中在两个界面（游戏助手、Scene）的刷新率档位，以及守护进程的几何/密度处理。

## 一、游戏助手

| 位置 | 之前 | 现在 |
|---|---|---|
| 悬浮面板 / 侧边栏 | 依赖混淆字段字母定位档位行，厂商一改包就整行不生效 | 按 dex 真实结构定位（选项包装视图的父容器 + 稳定 getter） |
| 我的游戏性能 → 显示设置 | 绑定对象写死混淆类名（tb0.t5），一类改名就静默跳过 | 按类型形状查找（持有 PerfSelectionStateView 的那个对象） |
| 档位来源 | 厂商框架表（含 123/150/155 占位档，且到 165 为止） | daemon 阶梯优先，安装时预热，首屏即正确 |
| 外观 | 圆角方块、单一选中色 | 4/5 列自适应胶囊芯片、实心绿选中 |

## 二、Scene 弹窗

- 接入**全部**刷新率节点：60/90/120/123/144/150/155/165；
- **4 个一行、两行全部显示、不用滚动**（hook PopupWindow.setHeight，仅对该弹窗加一行高度，不动布局权重）；
- 标签**裸数字**（与原生一致），颜色 8 种**互不重复**且按档位固定，选中为**自身颜色 + 白描边**。

## 三、守护进程

1. **悬浮窗宿主不再当普通 App**：`com.oplus.games` 在前台时保持游戏当前模式。
   现场日志：15:06:23–15:06:44 之间面板在 1272x2772 ↔ 1080x2354 之间震荡三轮，每次都是约 440ms 的
   `SurfaceFlinger physical mode` 变更 + 9 次 `settings put`。
2. **条目几何只影响刷新率**：条目里的分辨率只是写入那一刻的附带值，与当前几何不一致时只应用其刷新率。
3. **密度镜像按实际生效几何**：修复"面板在 FHD、却按 QHD 档写密度（560 而非 420）"导致的整机 UI 放大。

## 四、验证

- 游戏助手 App 页：`60/90/120/123/144` + `150/155/165` 两行，165Hz 实心绿选中；
- Scene 弹窗：8 档两行、4 个一行、无 Hz、8 色不重复、120Hz 白圈选中；
- 设置页（ColorOS 17）：`Settings front-page rates=[…]`，`NoSuchFieldException` 消失；
- 守护进程与两个 Hook APK 均编译通过。
