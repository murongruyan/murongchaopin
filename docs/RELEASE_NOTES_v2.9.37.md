# 慕容显示增强 v2.9.37


### 一、ColorOS 17（Android 17）全量适配

ColorOS 17 把整个 vendor 内核与显示 ABI 都换了一遍，旧版模块在 C17 上超频、刷新率、
设置页、投票补丁等全部静默失效。本版按机型逐项重新适配：

1. **内核符号契约守卫（动态检测内核符号）** —— 新增 `bin/ko_abi_guard` 与
   `scripts/ko_abi_guard.sh`。每次开机从设备自带的 vendor 模块里读出**当前内核真实的
   符号表与 CRC 契约**，加载每个内核增强模块前先比对：
   - 契约一致 → 直接加载随包模块；
   - 只是 CRC 变了 → 在 `runtime/ko_abi/` 生成适配副本后加载（原文件不改写）；
   - 契约里查不到的符号 → 去掉该符号的版本校验；
   - 必要符号已不存在 → 跳过该模块，并在 `runtime/ko_abi/status.txt` 与模块提示里说明。
   以后系统再 OTA 换内核，模块会自己重新检测，而不是整包失效。实测在 C17 上扫描出
   9807 个符号契约、53780 个导出符号。
2. **DRM 超频档注入适配 C17**：厂商解析出的时序数组位置、私有记录长度、MIPI PHY
   表偏移、panel 计数位置全部变化。模块改为**运行时光栅发现 + 校验**：只有每条记录都与
   设备树匹配、并且私有/PHY 布局通过校验时才写入，任何一条不匹配就整体拒绝（fail-closed），
   绝不盲改内存。四个机型（RMX5200 / PLK110 / PLQ110 / PJD110）的 DRM 模块都用固定
   流水线重建，并带 `.src.sha256` 指纹。
3. **SurfaceFlinger 投票过滤补丁适配 C17**：按构建契约自动分派（C16/C17 两套站点），
   并补上 `setIdleModeExternal` 的类型保护，避免 C17 上取到错误的重载。
4. **设置页（ColorOS 17）重建为 ColorOS 16 布局**：
   - 高刷新率页恢复**所有刷新率节点平铺**，不再只剩"极速高刷"一项；
   - 删掉 C17 新增的「刷新率设定」项，「自定义高刷新率应用」改回「自定义刷新率应用」；
   - 应用内刷新率选择改为**原生小弹窗**（圆角、分隔线、蓝色选中、跟随手指位置展开），
     不再是难看的整块大弹窗；
   - 超过屏幕高度时上下双向弹出，所有档位都能看到；
   - 列表只显示 **≥60Hz** 的档位（四端一致）；
   - 应用刷新率行为回归 C16 语义：未设置的应用跟随 `mode.txt` 第一行并标注「（默认）」，
     已设置的应用显示各自档位。
5. **WebUI 分辨率 / DPI 修复**：用 WebUI 切换分辨率时不再整体放大、不再闪退回桌面、
   不再让所有应用重载；分辨率落地后再写密度，并带快速回退。
6. **游戏助手 / Scene 联动**修复：三端（设置页、Scene、游戏助手）的目标类在 C17 上
   重新核对，投票补丁不再只服务 `stock_ltps`，`adfr_off` 同样接入（它也是固定刷新率方案，
   同样会被厂商残留的 AP-scale 映射表拖到 FHD 组，表现为来回黑闪）。
7. **视频动态插帧**在 C17 上恢复。
8. **修复系统卡顿**：daemon 之前每秒都 `dumpsys` 一遍系统服务，改为缓存 + 按需刷新，
   不再周期性卡顿。
9. **hmbird 调速器**：ColorOS 17 已下放 hmbird 调速器，检测到内核里已有就**跳过 DTBO
   修改**，不再重复打补丁。

### 二、删除「自制 LTPO」

**因某些原因，本版删除自制 LTPO。**

自制 LTPO 的方案是向显示驱动注入 1/10/30Hz 档位、再由守护进程做降频/升频来模拟 LTPO。
它在 ColorOS 17 上无法做到稳定：面板在直接改写时序的通路上会被拖到无效时序，表现为
花屏/黑屏、触摸失效，严重时整机卡死重启。反复定位后确认无法在保留功能的前提下修好，
因此本版整体移除：

- WebUI 刷新率策略不再提供「自制 LTPO」，只剩「原厂 LTPS」与「完美禁用 ADFR」；
- 自制 LTPO 专属的「禁用日常 LTPO」开关与息屏 AOD 时长设置一并移除；
- 开机不再注入 `rmx5200_ltpo_modes` / `rmx5200_ltpo_activity`，不再打 SurfaceFlinger
  的 LTPO rise / oti 补丁；
- 守护进程的自制 LTPO 空闲降档状态机不再启动；
- 之前选过自制 LTPO 的机器升级后自动回落到原厂 LTPS，不需要手动清理。

### 三、其它修复

1. 修复原厂 LTPS 空闲降档被投到 **170Hz** 超频节点的问题（SurfaceFlinger 的刷新率
   投票拿不到原厂 60 节点，落到超频档）；
2. QSync 空闲使能属性写在了 `post-fs-data` 的 `exit 0` 之后、实际从未执行，已修正
   （修复 `appRequest` 投票被写成 `[0,120]`）；
3. 不再发布 `persist.oplus.display.vrr.adfr`（写 2 会破坏原厂 60Hz 空闲降档）；
4. 开机自保护（防砖）机制在 PLQ110（一加 Ace 6）上生效：内核为
   `CONFIG_PANIC_ON_OOPS=y` 且 panic 后不自动重启，PLQ110 默认不加载任何注入用内核模块，
   回到已真机验证的 DTBO + props 方案；
5. 分辨率分组对齐、物理模式包络 hook 在 C17 上不再每次切档抛异常。
