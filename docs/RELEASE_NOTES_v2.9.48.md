# 慕容显示增强 v2.9.48

**这一版是回滚，请 2.9.47 的用户尽快升级。**

## 一、2.9.47 错在哪

2.9.47 试图省掉"每次亮屏抖两秒"的动作：只要三条证据成立就跳过亮屏恢复——
DisplayManager 的 applied 快照已是目标、厂商 ADFR floor（`min_fps`）≥ 目标、可读的实时 TE（`test_te`）一致。

真机反馈（PLK110，超频 185Hz，未设密码）证明这三条**会一起误判**：

- `min_fps` / `test_te` 是厂商**设置值**，不是实时面板时序——面板已经掉到 165 时它们照样读 185；
- DOZE 之后 DisplayManager 的 applied 快照也仍报目标档。

于是恢复被跳过，而面板实际停在 165——**再也没有人把它拉回来**，比 2.9.47 之前"抖两秒但最终正确"更糟。

## 二、本版做了什么

把 2.9.47 的跳过判定**整体回滚**，亮屏后恢复 2.9.46 的行为：先落到原生锚点，再按有序阶梯
爬回目标档，然后同步设置镜像。

- "每次亮屏抖一下"的问题**仍然存在**，这是已知代价；
- 但不会再出现"掉回 165 且不恢复"的情况。

## 三、得到的教训（写给下一次）

那两秒不是白抖的：它是目前**唯一**能确认扩展时序真的落到面板上的手段。要省掉它，前提是拿到一个
**实时**的面板时序来源——框架读数（SF `activeMode`、applied 快照）和厂商 `min_fps` / `test_te`
节点在 DOZE 后都不可信，必须先证明某个来源会随面板真实变化（真机对比：切档/掉档时读数同步变化），
再谈跳过。
